ArtyFarty est un gestionnaire d'artefacts personnel pour les utilisateurs de Claude. Cataloguez, versionnez, organisez et retrouvez tout ce que Claude crée pour vous — entre les conversations et sur tous vos appareils.

🗂 Arborescence de dossiers 📌 Historique de versions 🔄 Sync GitHub 📎 Fichiers joints 🤖 Suivi de session
Partie 1

L'application

Partie 2

Synchronisation GitHub

La sync permet à votre catalogue de vous suivre sur tous vos appareils. Vos métadonnées sont stockées en tant que artifacts.json dans un dépôt privé que vous contrôlez. Poussez après chaque session. Récupérez sur un nouvel appareil.

1
Créer un dépôt GitHub
Allez sur github.com → cliquez + → New repository.
Nommez-le comme vous voulez — ex. mes-artefacts. Mettez-le en Privé. Cliquez Create repository.

Un compte GitHub gratuit suffit.
2
Créer un jeton d'accès personnel (PAT)
Allez dans GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.

Configurez-le comme suit :
ParamètreValeur
NomArtyFarty (ou ce que vous souhaitez)
Expiration90 jours ou plus
Accès au dépôtOnly select repositories → votre nouveau dépôt
Permission ContentsRead & write
Permission MetadataRead-only
Important : Copiez le jeton immédiatement après sa génération — GitHub ne le montre qu'une seule fois. Conservez-le dans votre gestionnaire de mots de passe pour pouvoir le coller sur de nouveaux appareils.
3
Connecter l'application
Ouvrez l'application → cliquez ⚙ (en haut à droite) → renseignez :

Owner — votre nom d'utilisateur GitHub
Repo — le nom de votre dépôt
File path — artifacts.json
Token — collez votre PAT

Cliquez Save & Connect, puis ⬆ Push pour créer le fichier initial dans votre dépôt.
4
Utilisation au quotidien
L'application se synchronise automatiquement au chargement quand elle est configurée. Cliquez ⬆ Push après avoir ajouté ou modifié des artefacts. Sur un nouvel appareil, entrez le jeton une fois dans les Paramètres — puis Pull pour restaurer votre catalogue complet.
Partie 3

Skill de suivi de session

Installez ce Skill Claude une fois et il enregistrera automatiquement tout ce que Claude crée pour vous à la fin de chaque conversation — en générant un JSON delta que vous pouvez fusionner dans votre catalogue en quelques secondes.

1
Installer le skill dans Claude
Ouvrez Claude → panneau Skills (barre latérale gauche) → + New Skill.
Nommez-le artifact-manager-session-tracker.
Définissez le déclencheur avec une commande slash — ex. /artifact.
Collez le contenu du skill ci-dessous comme instructions.
2
Contenu du skill à coller
## Artifact Manager — Session Tracker

**If no artifacts were produced in this conversation — do nothing.**

If artifacts were produced, at session end generate the following
without being asked:

1. Print the filename in a copyable code block:
   artifacts-delta-YYYY-MM-DD-topic.json
   (topic = 2-3 word slug describing what was built)

2. Generate the delta JSON as a downloadable file

3. Produce each text artifact as a separate downloadable file
   (.py, .html, .js, .ts, .jsx, .css, .sql, .md, .sh,
    .yaml, .json, .xml, .txt)
   Binary files (.pdf, .xlsx, .docx, .pptx, .zip) —
   note these must be saved manually from earlier in the chat

## Historical Mode
If this skill is triggered on an old conversation, immediately
scan the full conversation history and generate the JSON and
individual files — do not wait for further instruction.

## JSON Format
{
  "exportedAt": "ISO timestamp",
  "exportType": "delta",
  "exportFilename": "artifacts-delta-YYYY-MM-DD-topic.json",
  "folders": [],
  "artifacts": [
    {
      "id": 7342,
      "name": "exact-filename.py",
      "desc": "One sentence describing what this does",
      "folder": null,
      "tags": ["relevant", "tags"],
      "starred": false,
      "createdAt": 1751050000000,
      "_updatedAt": 1751050000000,
      "versions": [
        {
          "v": "v1",
          "note": "What this version does",
          "preferred": false,
          "savedAt": 1751040000000
        },
        {
          "v": "v2",
          "note": "Final working version",
          "preferred": true,
          "savedAt": 1751050000000
        }
      ]
    }
  ]
}

## Rules
- Include EVERY file produced in the session
- Use the exact filename as the artifact name
- Mark the best/final version as "preferred": true
- Start artifact IDs from a random number between 5000-9999
- Set "folder": null — folders are assigned after importing
- Export type is always "delta"
3
Utilisation à la fin de chaque session
Après que Claude a créé quelque chose pour vous, tapez :
Déclencheur
/artifact
Claude produit deux choses :

① Un JSON delta — l'entrée de catalogue pour tout ce qui a été créé pendant la session. Téléchargez-le et fusionnez-le dans votre catalogue.

② Les fichiers individuels — chaque fichier texte créé (.html, .py, .js, .md, .json, etc.) est proposé en téléchargement séparé. Téléchargez chacun et attachez-le à sa carte dans l'application via le bouton 📎 Joindre — ainsi le vrai fichier accompagne les métadonnées.
4
Importer dans l'application
Téléchargez le JSON delta → ouvrez l'application → ⤴ Merge / load JSON → sélectionnez le fichier.
Les nouveaux artefacts sont ajoutés sans toucher aux existants.

Dépliez chaque nouvelle carte → 📎 Joindre → sélectionnez le fichier téléchargé pour l'attacher.
Partie 4

Skill de gestion des versions

Ce skill optionnel indique à Claude de ne jamais écraser un fichier directement — il sauvegarde toujours une copie versionnée au préalable. Si une modification tourne mal, la version précédente est à portée de main.

1
Installer le skill dans Claude
Ouvrez Claude → panneau Skills → + New Skill.
Nommez-le versioned-file-edits. Collez le contenu ci-dessous.
2
Contenu du skill à coller
## Versioned File Edits

Never overwrite a file that already exists. Always create a
versioned copy before or instead of overwriting.

## Versioning Scheme

Append a version suffix to the base filename before the extension:

  original:  phillip-artifact-manager.html
  version 2: phillip-artifact-manager-v2.html
  version 3: phillip-artifact-manager-v3.html

For files that already have a version number, increment it.
For files with no version, start at v2 (the original is v1).

## Workflow

1. Write the edited content to the NEXT version filename
2. Validate syntax before presenting:
   - HTML/JS: extract and parse the script block with node
   - Python: python3 -c "import ast; ast.parse(open('f').read())"
   - JSON: python3 -c "import json; json.load(open('f'))"
3. Keep only 2 versions: current + one rollback. Delete older ones.
4. Present the new file, state the version, what changed,
   and which version is available as rollback.

If validation fails: fix the issue before presenting.
Never present a file that has not been validated.
Never skip validation because the change was "small".
3
Fonctionnement en pratique
Quand vous demandez à Claude de modifier un fichier, il sauvegarde automatiquement la version précédente comme copie de secours, valide la syntaxe du nouveau fichier, puis vous présente la version mise à jour.

Vous avez toujours deux copies : la version courante et une version de secours — ce qui garde votre dossier propre tout en vous protégeant contre les mauvaises modifications ou les erreurs de troncature.

FAQ

Questions fréquentes

Est-ce que mes données sont envoyées quelque part ?
Non. Tout reste dans le localStorage de votre navigateur et dans votre propre dépôt GitHub privé. L'application ne fait aucune requête externe sauf vers l'API GitHub avec votre propre jeton.
Que faire si je vide mon navigateur ou perds le localStorage ?
Faites un Pull depuis GitHub — votre catalogue est toujours sauvegardé là sous forme de artifacts.json. C'est pourquoi configurer la sync est recommandé.
Ça fonctionne sur mobile ?
Oui — l'application fonctionne dans Chrome et Safari mobile. La sync GitHub fonctionne de la même façon ; entrez votre PAT une fois dans les Paramètres et il est mémorisé pour ce navigateur.
C'est gratuit ?
Complètement. Les comptes GitHub gratuits incluent des dépôts privés et l'accès API. L'application elle-même n'a aucun coût.
Puis-je l'héberger moi-même ?
Oui — téléchargez index.html et hébergez-le n'importe où (GitHub Pages, Netlify, ou ouvrez-le simplement en local). C'est un fichier unique sans étape de compilation ni dépendances.
Quelle est la bonne pratique pour les fichiers joints ?
Désignez un appareil comme principal — joignez les fichiers là et traitez-le comme référence. Les autres appareils récupèrent les métadonnées du catalogue via Pull mais n'auront pas les fichiers joints. Sur un appareil secondaire, utilisez le bouton 🤖 Reconstruire sur n'importe quelle carte pour générer un prompt Claude qui recrée l'artefact depuis zéro.
Les fichiers joints sont-ils inclus dans le Push GitHub ?
Non — le Push synchronise uniquement les métadonnées du catalogue (artifacts.json). Les fichiers joints sont stockés uniquement dans le localStorage de votre navigateur. Conservez vos copies locales en sécurité, et utilisez le prompt de reconstruction comme solution de secours si un fichier est perdu.
Quelle est la différence entre Push et Export complet ?
Push synchronise votre catalogue vers GitHub (recommandé pour une utilisation multi-appareils). L'export complet télécharge une sauvegarde JSON locale sur votre ordinateur — utile comme copie de sécurité supplémentaire.
