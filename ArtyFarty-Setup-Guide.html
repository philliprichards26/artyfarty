Part 2

GitHub Sync

Sync lets your catalogue follow you across devices. Your artifact metadata is stored as artifacts.json in a private repo you control. Push after every session. Pull on a new device.

1
Create a GitHub repository
Go to github.com → click + → New repository.
Name it anything — e.g. my-artifacts. Set it to Private. Click Create repository.

A free GitHub account is all you need.
2
Create a Personal Access Token (PAT)
Go to GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.

Configure it as follows:
SettingValue
NameArtyFarty (or anything you like)
Expiration90 days or longer
Repository accessOnly select repositories → your new repo
Contents permissionRead & write
Metadata permissionRead-only
Important: Copy the token immediately after generating — GitHub only shows it once. Store it in your password manager so you can paste it on new devices.
3
Connect the app
Open the app → click ⚙ (top right) → fill in:

Owner — your GitHub username
Repo — your repo name
File path — artifacts.json
Token — paste your PAT

Click Save & Connect, then ⬆ Push to create the initial file in your repo.
4
Day-to-day workflow
The app auto-pulls on load when configured. Hit ⬆ Push after adding or editing artifacts to keep GitHub in sync. On a new device, enter the token once in Settings — then Pull to restore your full catalogue.
Part 3

Session Tracker Skill

Install this Claude Skill once and it will automatically log everything Claude builds for you at the end of each conversation — generating a delta JSON you can merge into your catalogue in seconds.

1
Install the skill in Claude
Open Claude → Skills panel (left sidebar) → + New Skill.
Name it artifact-manager-session-tracker.
Set the trigger to a slash command — e.g. /artifact.
Paste the skill content below as the instructions.
2
Skill content to paste
## Artifact Manager — Session Tracker

**If no artifacts were produced in this conversation — do nothing.**

If artifacts were produced, at session end generate the following
without being asked:

1. Print the filename in a copyable code block:
   artifacts-delta-YYYY-MM-DD-topic.json
   (topic = 2–3 word slug describing what was built)

2. Generate the delta JSON as a downloadable file

3. Produce each text artifact as a separate downloadable
   (.py, .html, .js, .ts, .jsx, .css, .sql, .md, .sh,
    .yaml, .json, .xml, .txt)
   Binary files (.pdf, .xlsx, .docx, .pptx, .zip) —
   note these must be saved manually from earlier in the chat

## Historical Mode
If this skill is triggered on an old conversation, immediately
scan the full conversation history and generate the JSON and
individual files — do not wait for further instruction.

## JSON Format
{
  "exportedAt": "ISO timestamp",
  "exportType": "delta",
  "exportFilename": "artifacts-delta-YYYY-MM-DD-topic.json",
  "folders": [],
  "artifacts": [
    {
      "id": 7342,
      "name": "exact-filename.py",
      "desc": "One sentence describing what this does",
      "folder": null,
      "tags": ["relevant", "tags"],
      "starred": false,
      "createdAt": 1751050000000,
      "_updatedAt": 1751050000000,
      "versions": [
        {
          "v": "v1",
          "note": "What this version does",
          "preferred": false,
          "savedAt": 1751040000000
        },
        {
          "v": "v2",
          "note": "Final working version",
          "preferred": true,
          "savedAt": 1751050000000
        }
      ]
    }
  ]
}

## Rules
- Include EVERY file produced in the session
- Use the exact filename as the artifact name
- Mark the best/final version as "preferred": true
- Start artifact IDs from a random number between 5000–9999
- Set "folder": null — folders are assigned after importing
- Export type is always "delta"
3
Use it at the end of any session
After Claude has built something for you, type:
Trigger
/artifact
Claude produces two things:

① A delta JSON — the catalogue entry for everything built this session. Download this and merge it into your catalogue.

② Individual artifact files — every text file built (.html, .py, .js, .md, .json etc.) is offered as a separate download. Download each one and attach it to its card in the app using the 📎 Attach button — so the actual file lives alongside the metadata.
4
Import into the app
Download the delta JSON → open the app → ⤴ Merge / load JSON → select the file.
New artifacts are added without touching existing ones.

Expand each new card → 📎 Attach → select the downloaded file to attach it.
Part 4

Versioned File Edits Skill

This optional skill tells Claude never to overwrite a file directly — it always saves a versioned copy first. If an edit goes wrong, your previous version is one file away.

1
Install the skill in Claude
Open Claude → Skills panel → + New Skill.
Name it versioned-file-edits. Paste the skill content below.
2
Skill content to paste
## Versioned File Edits

Never overwrite a file that already exists. Always create a
versioned copy before or instead of overwriting.

## Versioning Scheme

Append a version suffix to the base filename before the extension:

  original:  phillip-artifact-manager.html
  version 2: phillip-artifact-manager-v2.html
  version 3: phillip-artifact-manager-v3.html

For files that already have a version number, increment it.
For files with no version, start at v2 (the original is v1).

## Workflow

1. Write the edited content to the NEXT version filename
2. Validate syntax before presenting:
   - HTML/JS: extract and parse the script block with node
   - Python: python3 -c "import ast; ast.parse(open('f').read())"
   - JSON: python3 -c "import json; json.load(open('f'))"
3. Keep only 2 versions: current + one rollback. Delete older ones.
4. Present the new file, state the version, what changed,
   and which version is available as rollback.

If validation fails: fix the issue before presenting.
Never present a file that has not been validated.
Never skip validation because the change was "small".
3
How it works in practice
When you ask Claude to edit a file, it automatically saves the previous version as a rollback copy, validates the new file's syntax, then presents the updated version.

You always have two copies: the current version and one rollback — keeping your folder clean while protecting against bad edits or truncation errors.

FAQ

Common Questions

Does this send my data anywhere?
No. Everything stays in your browser localStorage and your own private GitHub repo. The app makes no external requests except to the GitHub API using your own token.
What if I clear my browser or lose localStorage?
Pull from GitHub — your catalogue is always backed up there as artifacts.json. This is why setting up sync is recommended.
Does it work on mobile?
Yes — the app works in mobile Chrome and Safari. GitHub sync works the same way; enter your PAT once in Settings and it's saved for that browser.
Is it free?
Completely. GitHub free accounts include private repos and API access. The app itself has no cost.
Can I self-host it?
Yes — download index.html and host it anywhere (GitHub Pages, Netlify, or just open it locally). It's a single file with no build step and no dependencies.
What's the best practice for attached files?
Designate one device as your primary — attach files there and treat it as the source of truth. Other devices get the catalogue metadata via Pull but won't have the attached files. On a secondary device, use the 🤖 Rebuild button on any card to generate a Claude prompt that recreates the artifact from scratch — it's the safety net when the file isn't attached locally.
Are attached files included in the GitHub Push?
No — the Push only syncs your catalogue metadata (artifacts.json). Attached files are stored in your browser's localStorage only. Keep your local copies safe, and use the Rebuild prompt as a fallback if a file is ever lost.
Push syncs your catalogue to GitHub (recommended for cross-device use). Full Export downloads a local JSON backup to your computer — useful as an extra safety copy.
